# 答辩演示设计

## 演示目标

评委需要在五分钟内理解三件事：项目怎样接入 IREE 的完整下降链，权重排布怎样改变单阵列中的计算方式，以及这些变换组合后产生了什么结果。

整套演示按工作领域展开。第二页先建立全貌，随后依次介绍 IREE 全流程接入、IR/Pass 设计、权重排布和 SRAM 资源管理。权重排布是讲解重点，因此拆为优化思路、优化效果和二维切分三页。

## 幻灯片设计

### 第 1 页：面向单阵列 CIM 的端到端编译器

封面只保留项目名称、副标题和 `ONNX → IREE → CIM ISA`。页脚填写团队名称与答辩人。

讲稿：

> 各位评委好。我们实现了一套接入 IREE 的 CIM 编译后端，输入 ONNX 模型，输出能够由 CIM 驱动加载和执行的 VMFB。下面重点介绍完整编译流程、权重排布及其优化效果。

### 第 2 页：工作全貌

用一条横向主线介绍四个工作领域，页面标题只写“工作全貌”：

```text
编译主线              目标语义           阵列空间             动态存储
IREE 全流程接入  →  IR/Pass 设计  →  权重排布  →  SRAM 资源管理
```

每项工作只保留一个结果说明：

- IREE 全流程接入：模型导入到 VMFB 执行；
- IR/Pass 设计：逻辑操作到物理 ISA；
- 权重排布：优化排布与二维切分；
- SRAM 资源管理：活跃期分析与地址复用。

讲稿：

> 我们的工作沿一条编译链展开。IREE 提供从模型导入到可执行文件的主干；CIM IR 和 Pass 保存并逐步落实目标语义；权重排布解决单阵列中的合法放置与计算优化；SRAM 管理最后为动态对象分配物理地址。后面按这个顺序介绍。

### 第 3 页：IREE - 全流程接入

直接使用报告中的 [IREE–CIM 架构图](assets/iree-cim-architecture.svg)，不另画简化架构。页面只增加一句结果说明：

> CIM 后端沿 IREE 原生阶段介入，最终生成 VMFB、CIM 指令和权重载荷。

讲稿：

> 这张图是项目的完整下降路径。ONNX 导入后，IREE 负责图级变换、任务形成、HAL 封装和可执行文件链接；CIM 后端在需要目标语义的阶段介入，完成目标翻译、全模型权重处理、位串行展开和 SRAM 地址分配。最终的 CIM 指令与权重载荷随 VMFB 一起交给驱动执行。

### 第 4 页：IR/Pass 设计

使用 [CIM IR、Pass 与 ISA 映射图](assets/cim-ir-pass-isa-mapping.svg)，展示以下下降关系：

```text
IREE / MLIR 高层操作
→ 逻辑 CIM IR
→ 链接后物理化 Pass
→ 物理 CIM IR
→ ISA 指令
```

讲稿：

> 高层 Linalg 保留矩阵语义。切分和异构融合在进入 CIM IR 之前完成。缓冲区化后，逻辑 CIM IR 表达 MVM 与数据搬运，横向拼接和权重复制在这一层改写权重视图。阵列规划确定坐标后，后续 Pass 补上输入位编号和 SRAM 地址，并逐条映射到 ISA。

### 第 5 页：权重排布 - 优化

使用 [三种权重优化排布图](assets/weight-optimization-primitives.svg)，完整保留激活值、权重矩形、结构零和优化前后对照。

页面底部只保留提交条件：

> 候选布局只有在全模型权重仍能放入唯一阵列时才会提交。

讲稿：

> 三种优化对应三类复用关系。共享一个激活值的多组权重沿 N 方向拼接，四次 MVM 合成一次，阵列占用不变。不同激活值进入不同权重时，激活值相邻放置、权重排成块对角矩阵。连续多行共享同一权重时，复制权重并排成块对角区域，让多行并行执行。后两种方法会增加结构零或副本，因此编译器先生成候选布局，再检查单阵列容量。

### 第 6 页：权重排布 - 优化效果

使用 [综合用例优化前后图](assets/integrated-before-after.svg)，保留：

- 单阵列 `1024×512` 边界；
- 优化前后的权重区域；
- 独立 producer `U0/U1`；
- 激活值与矩形选择；
- 块对角结构零。

页面右侧只强调两项运行工作量：

```text
MVM 窗口：24 → 8 (−66.7%)
位计算轮次：384 → 160 (−58.3%)
```

讲稿：

> 综合用例把三种优化放进同一个模型。左边是优化前的九个权重区域，右边仍是同一块 1024×512 阵列：共享输入权重被横向拼接，两块异构权重组成块对角区域，四行共享的权重复制为另一个块对角区域。U0、U1 和所有激活值仍按对应矩形参与计算。组合后，全模型 MVM 窗口由 24 个降到 8 个（降幅 66.7%），位计算轮次由 384 轮降到 160 轮（降幅 58.3%）。

### 第 7 页：权重排布 - 切分

使用 [二维合法化图](assets/legalization-before-after.svg)。页面将两个方向的结果分别标为：

- N 方向：相邻输出区间；
- K 方向：部分和累加。

讲稿：

> 权重超过阵列列容量时，编译器沿 N 方向均匀切分，各分块写入相邻输出区间；超过阵列行容量时，沿 K 方向切分，再显式累加部分和。当前实现只选择能够整除的分块，不引入填充。这个用例同时包含两种超尺寸权重，并把四个分块共同放入唯一阵列。

### 第 8 页：SRAM 资源管理

使用 [SRAM 生命周期复用图](assets/sram-lifetime-before-after.svg)，对比顺序分配和活跃期复用。页面只强调：

```text
SRAM 地址峰值：16,384 B → 10,240 B (−37.5%)
（相对未优化基线 12,288 B 降低 16.7%）
```

讲稿：

> 动态对象在位串行展开后已经全部显式进入 IR。分配器通过别名闭包和活跃期分析确定每个对象的生命周期，让互不重叠的对象复用地址。综合用例中，横向拼接引入的目的视图复制使顺序分配峰值上升至 16,384 字节；生命周期复用将其大幅压降至 10,240 字节（降幅 37.5%，相对未优化基线降低 16.7%），计算指令和权重布局保持不变。

### 第 9 页：实验结果

使用 [综合优化与单变量消融图](assets/optimization-evidence.svg)，不再把同一组指标拆成右侧数字面板。页面底部保留两行结论：

```text
MVM 窗口 −66.7%　位计算轮次 −58.3%　SRAM 峰值 −37.5% (相对基线 −16.7%)
全套官方模型与自建用例均与 ONNX Runtime 逐位一致；自动化测试全部通过
```

讲稿：

> 综合用例中，MVM 窗口减少 66.7%，位计算轮次减少 58.3%，SRAM 地址峰值相对拼接后降低 37.5%（相对未优化基线降低 16.7%）。相应的部署成本是阵列占用从 15.62% 增至 28.12%，载荷增加 33.0%。单变量消融将这些变化归因到对应 Pass。数值验证覆盖官方模型和全部自建用例，均与规范化 ONNX 的 ONNX Runtime 结果逐位一致；自动化测试全部通过。

### 第 10 页：结论

页面中央只保留最终交付：

> 从 ONNX 到单阵列 CIM 物理程序

下方用两条结果收束：端到端链路可执行，优化排布可组合。二维切分、SRAM 地址分配和数值校验放在同一句说明中，不再重复实验指标。

讲稿：

> 我们完成了一条能够生成并执行 CIM 物理程序的编译链。权重优化、二维切分和 SRAM 地址分配在同一份程序上连续完成，综合用例展示了组合优化的效果。我的介绍到这里。

## 视觉规范

- 画幅为 16:9，白底，深蓝标题，青色标题定位线。
- 页面标题使用工作领域名称，不使用宣传式结论句。
- 报告图直接作为页面主视觉，不拆成卡片阵列。
- 图外文字只承担标题、指标和解释图意三个功能。
- 演示源码为 `typst/presentation.typ`，口播讲稿见 `presentation-speech.md`；页面不显示时间和转场提示。
- “阵列占用”指部署矩形面积，包含块对角结构零。
- “位计算轮次”指最终物理程序中的 `cim.bit` 数量，不等同于芯片实测时延。
