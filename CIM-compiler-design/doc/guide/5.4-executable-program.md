# 5.4　可执行载荷与指令序列化：从物理 IR 到 Payload 与 ISA

经过全局阵列规划（`CIMPlanArrayPass`）、位串行展开（`CIMExpandBitSerialPass`）以及 SRAM 活跃期地址分配（`CIMAllocateSRAMPass`）之后，CIM 程序已完全收敛为物理 IR：
* 部署入口 `@__cim_array_init` 包含固定阵列坐标的 `cim.array.load` 权重写入指令；
* 各计算入口包含完整的输入搬运、8 或 32 轮 `cim.bit` 位串行驱动、`cim.elt` 加权累加重构以及输出回写指令；
* 所有操作数均已具备确定的内存视图与绝对 SRAM 字节偏移。

`CIMExecutablePayload` 模块的作用是将物理 IR 序列化为 Runtime 直接驱动硬件的二进制载荷（Binary Payload），并同步生成用于调试与静态审计的文本反汇编（`.cim.isa`）。

---

## 5.4.1 二进制载荷架构 (Binary Payload Layout)

CIM 可执行载荷以紧凑的字节对齐二进制格式编码，包含header、三个定长记录表、string table 和 data segment：

```text
+-------------------------------------------------------------+
|                      Payload Header                         |
|   (magic, version, num_exports, num_views, num_ops, etc.)   |
+-------------------------------------------------------------+
|               Export Table (ExportDef[])                    |
|   (name_offset, name_len, program_start, program_count)     |
+-------------------------------------------------------------+
|             Buffer View Table (BufferViewDef[])             |
|   (storage_kind, ordinal, dtype, rank, offsets, extents...) |
+-------------------------------------------------------------+
|            Instruction Table (ProgramOpDef[])               |
|   (opcode, view0, view1, view2, mode, immediate...)         |
+-------------------------------------------------------------+
|               String Table (Export Names)                   |
+-------------------------------------------------------------+
|             Data Segment (Embedded Constants)               |
+-------------------------------------------------------------+
```

1. **导出表 (`ExportDef`)**：记录每个 HAL Entry Point 的入口名称以及该任务在操作表中的起始指令索引与指令数量；
2. **缓冲区视图表 (`BufferViewDef`)**：将程序中的所有操作数统一抽象为包含存储类别、数据类型、二维几何尺寸和仿射偏移表达式的统一结构；
3. **指令表 (`ProgramOpDef`)**：以 32 字节定长格式编码每条硬件操作（Array Load、Bit-Serial MVM、Elt、MemCopy 等）及其引用的视图索引（`view0`, `view1`, `view2`）。

---

## 5.4.2 统一视图回溯机制 (`resolveBufferBase`)

在 MLIR 代码生成过程中，内存对象常被多层 `memref.subview`、`memref.view`、`memref.transpose` 以及强制对齐等 View-Like 算子包装。序列化构建器（`PayloadBuilder`）复用 `CIMMVMUtils::resolveBufferBase` 解析物理存储根节点；同一函数也服务于静态权重读取和 SRAM 覆盖证明：

```text
Value (Operand)
   │
   ▼ (while DefiningOp is ViewLikeOpInterface)
[ 迭代剥离 SubViewOp / ViewOp / TransposeOp ] ──> 按原生 subview/reinterpret/byte-view 语义归约字节偏移
   │
   ▼
[ 判定最终 Storage Root ]
   ├── GetGlobalOp (MemorySpace = Array)      ──> CIMX_STORAGE_ARRAY
   ├── GetGlobalOp (ordinary constant)  ──> CIMX_STORAGE_EMBEDDED_DATA
   ├── AllocOp (SRAM Arena)                   ──> CIMX_STORAGE_SRAM
   └── HAL InterfaceBindingSubspanOp       ──> CIMX_STORAGE_BINDING
```

* **四类物理存储空间**：
  1. `CIMX_STORAGE_ARRAY`：存算阵列全局权重，视图偏移记录其在 $1024 \times 512$ 阵列上的绝对行/列坐标；
  2. `CIMX_STORAGE_SRAM`：片上 SRAM 局部暂存，视图偏移记录由活跃期分配器决定的绝对字节地址；
  3. `CIMX_STORAGE_BINDING`：Host 传入的输入输出张量，视图保留其在 HAL 接口中的参数序号；
  4. `CIMX_STORAGE_EMBEDDED_DATA`：内嵌偏置与静态标量常量，直接打包入载荷的数据段。

## 5.4.3 静态仿射表达式折叠 (`foldIndex`)

对于多行工作组程序（如 $M_T = 4$ 的调度配置），不同 Workgroup 实例在运行时需要读取不同批次的输入行。序列化构建器通过 `foldIndex` 分析地址索引计算中的 Workgroup 坐标：

\[
\text{Offset} = \text{base} + a \cdot \text{workgroup\_id.x} + b \cdot \text{workgroup\_id.y} + c \cdot \text{workgroup\_id.z}
\]

编译器提取仿射线性项系数 $(a, b, c)$ 并编码入 `BufferViewDef.offsetX/Y/Z`。地址系数由 MLIR `ValueBoundsConstraintSet` 的 EQ 关系求得，再展开为整数线性项。
中间算术须无溢出，最终常量项、系数、extent、字节 stride 都必须能表示为非负 u32。
Runtime 根据当前工作组坐标计算地址，使同一程序覆盖整个网格。

## 5.4.4 二进制 Payload 与 ISA 文本的反汇编同源投影

在生成二进制 Payload 的同时，序列化流水线同步生成文本格式的 `.cim.isa`：

```isa
// .cim.isa 片段：deployment 与 compute 的同源投影
.deployment @__cim_array_init
cim.array.load.i8 embedded[0], 0, 0, 256, 256

.runtime @main_dispatch_0
mem.copy.i8.i8 0, binding[0, 0], 256
cim.bit.i8.i8 1024, 0, 0, 0, 0, 256, 256
elt.add.i32.vv 2048, 2048, 1024, 256
```

* **文本 `.cim.isa`**：提供完全可读的静态指令清单，用于验证阵列排布、位串行轮次与 SRAM 峰值；
* **二进制 `.cim.payload`**：直接嵌入 `hal.executable.binary` 并打包进最终的 VMFB 动态模块，由 Runtime 的原生 CIM HAL Driver 驱动执行。
