# 2　Dispatch 形成：保留共享输入关系

IREE 用 dispatch 表示一次可以提交给目标设备的计算任务。dispatch 边界形成后，后端通常只在单个任务内部改写计算，因此共享输入的矩阵乘需要在这个阶段进入同一边界。

设一行激活值 \(x\) 同时送入多个权重：

\[
y_i=xW_i.
\]

IREE 的横向 contraction 融合将这些矩阵乘组织成同一个 dispatch。它保留各自的结果和权重，改变的是任务边界：后端随后可以同时看到这些计算，并决定是否把权重沿 N 方向拼接。

dispatch 形成后，Flow 将任务轮廓化为 executable，Stream 再安排资源、时间线和命令。静态权重随 executable 进入目标代码生成，主程序则通过 dispatch binding 传递输入输出。CIM 在这两个阶段继承 IREE 的任务与资源语义。

共享输入关系由此保留在同一个目标任务内。权重继续采用逻辑布局进入后续阶段，链接得到完整部署后再完成物理拼接。
