# 4.2　逻辑 CIM IR：算子语义与可链接边界

经过分块合法化与 IREE Comprehensive Bufferization 之后，张量（Tensor）级别的计算已被完全降低为基于结构化内存视图（`memref`）的显式内存操作。在此边界上，`CIMConvertLinalgToCIMPass` 将通用的 Linalg 算子转换为目标专用的**逻辑 CIM IR**（Logical CIM Dialect）。

逻辑 CIM IR 是前端图级计算与后端物理硬件之间的关键桥梁：它明确定义了 CIM 存算单元与片上协同逻辑所执行的计算语义，同时保持全局权重符号的逻辑引用，为后续 HAL 链接阶段的权重全局优化排布留出充分的改写空间。

---

## 4.2.1 核心逻辑算子及其内存语义

逻辑 CIM Dialect 采用严格的目标传递风格（Destination-Passing Style, DPS），所有计算结果均通过显式的 `outs(...)` 操作数接收目标缓冲区。数据搬运直接使用原生 `memref.copy`。

```mlir
// 1. 逻辑矩阵向量乘 (MVM)
cim.mvm ins(%src_tile, %weight_global : memref<1x256xi8>, memref<256x64xi8>)
        outs(%dst_buffer : memref<1x64xi32>)

// 2. 整数逐元素计算 (Elt)
cim.elt <add> <vv> ins(%src0, %src1 : memref<64xi32>, memref<64xi32>)
               outs(%dst : memref<64xi32>)
cim.elt <mul> <vi> ins(%src0 : memref<64xi32>)
               outs(%dst : memref<64xi32>) <{immediate = 16 : i64}>

// 3. 原生内存拷贝
memref.copy %src, %dst : memref<256xi8> to memref<256xi8>
```

### 1. 逻辑矩阵向量乘 (`cim.mvm`)
* **几何约束**：固定为 Rank-2 矩阵运算 `[1, K] × [K, N] -> [1, N]`，严格对应硬件阵列上的单次窗口计算；
* **操作数语义**：输入激活 `%src_tile` 与静态权重 `%weight_global` 均为只读；输出 `%dst_buffer` 采用**纯覆写语义**（Overwrite），不读取历史数据；
* **位宽规则**：输入支持 signed `i8` 与 `i32`，输出直接写入 32 位整型累加结果（`i32`），无需生成多余的 64 位临时累加器。

### 2. 整数逐元素运算 (`cim.elt`)
* **几何约束**：操作数固定为展平的 Rank-1 视图（`memref<L x T>`）；
* **操作模式**：
  * **向量-向量模式 (`vv`)**：支持片上两块缓冲区之间的逐点加法（`Add`）、减法（`Sub`）、乘法（`Mul`）与除法（`Div`）；
  * **向量-立即数模式 (`vi`)**：支持缓冲区与编译期立即数（`immediate`）之间的算术运算；
* **应用场景**：统一承接偏置相加、归约 $K$-Tile 的部分和累加、以及后续位串行展开的权重移位重构。

### 3. 原生内存拷贝 (`memref.copy`)
* **应用场景**：在 HAL 外部绑定缓冲（Binding）与片上 SRAM 之间导入输入激活或导出最终结果，以及在 SRAM 内部执行连续数据重排。

## 4.2.2 零初始化直写优化 (Zero-Init Elision)

在 Linalg 原生代码生成中，矩阵乘累加通常以 `linalg.fill(0)` 初始化目标缓冲区，再通过累加将点积结果写入。若机械翻译为 CIM 指令，将导致一次多余的零填充和一次多余的 `cim.elt add` 累加。

CIM 转换模式在生成 `cim.mvm` 时执行同一 block 内的 reaching-write 分析：
* **零初始化消除**：沿同一 block 向前扫描，若最近的相关访问是对同一目标的 `linalg.fill(0)` 或 constant zero-global copy，且输入与输出无别名，转换器直接将该缓冲区作为 `cim.mvm` 的目标，并消除零初始化；任何可能的目标读写或未知效应都会阻断扫描；
* **部分和累加**：仅当目标缓冲区包含不可覆盖的前序有效数据（例如多 $K$-Tile 切分中的后续部分和）时，才分配同形临时暂存（Scratch），并通过后续的 `cim.elt add` 累加进目标。

## 4.2.3 延迟物理化的可链接边界

目标翻译完成后的逻辑 CIM IR 具有以下关键特性：
1. **指令直线化**：函数内部不再包含复杂的张量操作，全部计算均已降低为顺序执行的 CIM 逻辑指令；
2. **符号引用保留**：权重操作数仍指向未分配物理坐标的全局常量（`memref.get_global`）；
3. **硬件解耦**：尚未引入硬件底层的阵列坐标（$X_0, Y_0$）、权重重编程指令、8 轮位串行驱动循环以及 SRAM 绝对物理字节地址。

这一设计构成了**延迟物理化（Late Physicalization）**的核心边界：它允许编译器在 HAL 链接阶段汇集模型内的所有 Executable 实例，在各既有入口内执行横向拼接与权重多行复制，再由阵列规划器确定物理布局。异构融合已在 preprocessing 完成。
