# 融合、权重复制和内存复用，为什么分在不同阶段

线性层在图中只有一条矩阵乘；进入一个四行工作组后，它成为四条 `cim.mvm`，再通过权重复制合成一条。看清这次 `1 → 4 → 1`，就能理解 IREE 的任务融合、CIM 的目标计算合并和存储复用各自解决什么。

目标阵列包含 `1024×512` 个 i8 权重单元。本文从 `weight_replication_showcase` 出发。输入 X 为 `[8,256]xi32`，逻辑权重 W 为 `[256,128]xi8`，矩阵乘产生 `[8,128]xi32` 结果。目标配置让每个工作组处理四行，两个工作组执行同一份程序。

## 一层矩阵乘，为什么会下降成四条 MVM

先看其中一个工作组。高层计算是四行激活共同使用 W：

```text
Y = X_group @ W                  X_group: [4,256]
```

CIM 的逻辑 MVM 以一行激活为单位，因此 tiling 与 bufferization 后得到：

```text
x0 @ W → y0
x1 @ W → y1
x2 @ W → y2
x3 @ W → y3
```

四次计算用的是不同输入行，权重相同。若按这份程序逐条展开，每条 i32 MVM 都需要 32 轮 bit 计算，工作组内合计 128 轮。权重复制尝试用更多阵列空间，把这四行一起计算。

这里已经出现两个层次：IREE 确定了工作组要处理四行，CIM 后端再决定这四行怎样使用阵列。

## 三种组合分别利用什么关系

“把多个计算合起来”需要先说明共享的是什么：

| 原计算 | 组合方式 | 利用的关系 |
| --- | --- | --- |
| `x @ W0`、`x @ W1` | `x @ [W0 W1]` | 同一个激活，沿输出列拼权重 |
| `x0 @ W0`、`x1 @ W1` | `[x0 x1] @ diag(W0,W1)` | 独立输入与权重，用块对角隔开 |
| `x0 @ W`、`x1 @ W` | `[x0 x1] @ diag(W,W)` | 不同行共享权重，把副本放在对角块 |

本项目在 preprocessing 对独立异构 contraction 做图改写，并调用 IREE 原生横向 contraction fusion 组织共享激活的计算。原生 dispatch formation 随后形成任务，Flow 再把任务提取成 executable。[插件接入](../../compiler_plugins/cim/src/PluginRegistration.cpp)

对共享激活的情况，高层横向融合先让多路计算进入同一个可编译任务；链接后的 horizontal packing 再把权重实际拼成一个矩形。前面的图组织为后面的物理组合创造机会。

权重复制利用的则是本例四条逐行 MVM 的关系。这种关系要等逐行计算与输入输出视图形成后，才能直接在目标程序中改写。

## 为什么选择链接之后、Array 放置之前

此时改写已经具备三类信息：

- **计算形态**：一条 `cim.mvm` 就是一行输入对应的一次逻辑阵列计算。
- **存储关系**：MemRef 子视图说明 x0–x3、y0–y3 是否相邻，能否直接组成更宽的视图。
- **部署成本**：链接汇集了仍被各入口使用的静态权重，可以检查复制后整套权重是否放得下。

因此 `CIMReplicateWeightMVMsPass` 可以把四条 MVM 改为：

```text
[x0 x1 x2 x3] @ diag(W,W,W,W) → [y0 y1 y2 y3]
```

接下来的 Array planner 再给这个新矩形分配坐标。先确定最终权重形状，后确定它放在哪里，两个决定便自然衔接起来。[链接后管线](../../compiler_plugins/cim/src/cim/Codegen/CIMPasses.cpp)

对本例，四行共用一份工作组程序。生成的块对角权重常驻阵列，两个工作组分别用自己的四行输入访问同一布局；公开调用接口与工作组网格继续沿用 IREE 的安排。

## 计算合并后，资源规划接着解决什么

合并成功后，一条 MVM 仍需 32 轮，但输出从一行的 128 个元素扩大为四行合起来的 512 个元素。计算次数减少，常驻权重和位串行暂存所需的空间随之变化。

Array planning 为最终权重矩形选择二维坐标；SRAM allocation 则为激活、结果和暂存选择字节地址。前者根据矩形大小与内容去重放置，后者根据缓冲区的同时存活关系复用空间。

从这个例子看，三种工作顺着数据逐步落实：先组织任务，再利用逐行 MVM 与连续视图合并阵列计算，最后为确定下来的对象安排存储。下一篇[权重复制实现](weight-replication-implementation.md)继续追踪这条块对角 MVM 怎样产生。
