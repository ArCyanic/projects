## 研究主线与贡献

3D CIM 提供大规模权重常驻的硬件条件。MoE 推理需要在这些驻留权重上组织随路由变化的计算与通信，推进跨层数据依赖，并评价部署与运行策略。本文以共同的硬件抽象连接空间可行性与执行时间，建立部署、执行和分析框架，再优化权重映射与数据流调度。

第三章对应第一项贡献，第四章先建立框架，再介绍算法。第五章用整体效果、硬件配置对照和调度消融验证这三项内容。

### 原型与术语的使用

统一模型以 3D CIM 的存储组织、计算资源与执行时间为研究对象。Jang 等人的 [3D NAND Flash PIM](https://arxiv.org/abs/2511.12860) 对应 jang2025，[3D-FPIM](https://doi.org/10.1109/MICRO56248.2022.00093) 对应 lee2022；这两篇工作提供代表性机制、参数标定与实验配置的依据。第三章先定义一般的资源与时间关系，再以两类配置说明模型如何实例化。其他架构可依据其存储组织、计算机制与读出方式，在同一抽象下给出相应配置和时间关系。

前两章用“硬件抽象与代价模型”概括其作用，Weight-Cube 在第三章首次定义。定义时交代三维尺寸、算子执行时间与输入输出字节数，字节数按激活张量长度和位宽计算。算子执行时间 $T_c$ 覆盖节点内输入装载至输出写出，专家执行时间 $T_e$ 为 gate/up 与 down 权重块时间之和；Mesh 传输与节点、链路争用由完整执行模型评价。

涉及时间使用“计算时间”“执行时间”或“传输时间”；涉及数据体积使用“输入输出字节数”或“通信载荷”。动作首次出现、切换讨论对象或存在多种解释时补全对象，同一语境沿用明确的简称。句子用具体动作说明对象之间的关系，修饰词按其增加的信息选择；“直接”等方式修饰词在句义完整时删除。

## 2 Background and Motivation

本章先介绍 3D CIM 与 MoE 的基础机制。相关工作比较支撑硬件模型和部署、执行框架两项贡献；算法动机同时覆盖离线权重映射与运行时数据流调度。图 1 以一个固定权重布局说明节点共驻及副本位置，并对照两种 Decode 执行；Prefill 的跨专家节点工作量问题由短段承接。

### 2.1 3D CIM and MoE

第一段从 CIM 的矩阵权重存储与阵列内矩阵向量乘法讲起。模拟实现通过输入信号驱动已编程的单元，以电流或电荷累加表达加权和，再经读出电路数字化；随后介绍 3D CIM 的垂直权重存储层、单位面积容量及共享输入／读出电路（`@jang2025, @lee2022, @buchel2025`）。本段提供物理计算过程，具体硬件层级和串行执行约束由第三章定义。

第二段介绍 MoE 层怎样以专家 FFN 集合替代稠密 FFN：门控网络逐 Token 选择 Top-$k$ 专家，选中专家处理相同输入向量，输出按门控权重组合；共享专家作为部分模型的附加结构单独说明（`@switch2022, @deepseekmoe2024`）。最后用处理提示词与自回归生成后续 Token 定义 Prefill／Decode，具体计时方式和窗口规模留给后文。

本节承担基础知识介绍。副本实例及权重重排的含义在 2.2 图示前说明，规约根在示例首次定义；四级硬件抽象、`Weight-Cube` 和 `Planar/Vertical` 由第三章定义，具体调度规则由第四章说明。

### 2.2 Related Work and Motivation

本节的文献比较围绕第一、第二项贡献展开，随后用三个短段建立第三项贡献的映射、Decode 调度及 Prefill 调度动机。图中的运行时差异在同一部署上测量，复制与结构重排的空间配置作用在正文中解释。

**硬件模型比较。** CIM 编译框架在二维阵列上表示权重与执行时间；3D AIMC 将矩阵块映射到 tile/tier，OPTIMEX 将专家投影映射到异构 cube/tier。基于这些实际表示说明本文如何共同描述三维块容量及不同计算、读出机制下的执行时间。

**部署与执行评价比较。** 3D AIMC 的 Token 操作图包含 tile/DPU 等资源调度，传输采用固定每比特时间且省略互连争用；OPTIMEX 的放置目标包含激活次数加权的垂直层距。本文连接容量可行的部署与路由驱动的跨层执行评价，以共同部署比较 Decode／Prefill 并分析节点与链路瓶颈。

**权重映射动机。** 共激活专家共享节点时串行计算，分散布局可能增加激活传输。空间重排根据路由轨迹调整共驻关系与传输距离，复制利用额外容量提供其他执行位置；两类动作共同服务受容量限制的部署选择。

**Decode 数据流调度。** 图 1 保留一个共享的 $2\times2$ Mesh 区域：E1、E2 位于 N1，E2 的另一权重实例位于 N4，E3 位于 N5，源为 N0。最近副本与源节点汇聚产生 $6\tau$，联合选择 E2@N4 及 N5 汇聚产生 $4\tau$。所有权重位置保持不变，计算与返回传输由两条时间轴呈现；规约根首次在正文定义，并成为下一 FFN 的输入源。

**Prefill 数据流调度。** 逐专家轮转分别分配请求，却忽略不同共驻专家在同一节点上的累计工作。分派依据节点累计分配的执行时间，通信树规则由第四章说明。节点总工作量与算子、传输时间的共同评价接入第三章，机制实验由第五章调度消融提供。

## 3 Hardware Abstraction

第三章对应第一项贡献“统一的硬件抽象与代价模型”，作为纯粹的静态契约与数学模型层，包含 `3.1 Architecture Model`（3 段）与 `3.2 Cost Model`（2 段）。**算子矩阵分片相加/拼接、垂直累加深度 $d$ 的择优以及节点三维装箱过程全部移至 `4.2.1 Weight Deployment`**，本章绝不抢占。

`3.1 Architecture Model`：
- **第一段（四级组织与互斥约束）**：配合硬件图（Figure 2a–c）自底向上定义 `Unit-Cube`（垂直堆叠存储微元）、`Sub-Cube`（存内计算单元，受共享外围电路与单层激活约束，同一时刻仅执行单路矩阵乘加）、`Node`（集成 Sub-Cube 与路由接口的计算节点）与 `2D Mesh`（片上网络）。
- **第二段（两类计算与读出范式）**：配合 Figure 2d 首次正式定义 **平面存内计算（Planar）**（局部权重平铺二维阵列，逐层激活并由 ADC 独立量化读出，经数字加法树规约）与 **垂直累加（Vertical）**（输入切片沿深度折叠，多层电流/电荷在垂直位线原位模拟累加，顶层经单次 ADC 量化后在数字域聚合）。
- **第三段（Weight-Cube 统一表征）**：首次正式定义 `Weight-Cube`：将映射至节点的权重块统一表示为三维几何尺寸 $(H_c, W_c, D_c)$、算子执行时间 $T_c$ 与输入输出字节数 $(V_c^{\text{in}}, V_c^{\text{out}})$（删除单次出现的 $\mathcal{H}(c)$ 函数记号）。说明三维尺寸对接节点容量约束，$T_c$（含输入装载、阵列计算、结果合并与写出）对接节点内算子耗时，输入输出字节数对接链路传输载荷。

`3.2 Cost Model`：
- **第一段（Planar 与 Vertical 算子执行时间公式）**：给出给定输入切片数 $S$、输出区间数 $Q$ 与垂直累加深度 $d$ 下的闭式算子执行时间公式 $T_c^{\text{P}}$ 与 $T_c^{\text{V}}$，阐明输入发射、模拟累加、ADC 量化与数字合并各分项的物理意义，以及给定深度 $d$ 如何同时影响模拟累加时间与数字合并次数（4.2.1 据此选择最优深度 $d$）。
- **第二段（原型参数标定与单跳传输时间）**：说明两类配置如何依据 Jang 等人的 3D NAND PIM（`@jang2025`）与 `3D-FPIM (@lee2022)` 标定参数；定义输入输出字节数按激活张量长度与位宽计算，给出有向 Mesh 链路单跳传输时间 $t_{\text{hop}}(V) = \lceil V / B_{\text{mesh}} \rceil$，明确节点内串行与链路争用产生的等待在第四章执行模型中处理。

几何对齐、装箱步骤、候选深度枚举、完整推导、分段累计和具体算子代入由补充材料承接。每段以物理实体和动作组织，公式前后形成连续解释。

### 4.2.1 Weight Deployment

本节以适中篇幅解释从算子到硬件权重块的转换，按“输入与约束—块的形成与时间—位置与部署输出”组织三个相接的段落。读者应理解转换为什么发生、怎样形成可执行块，以及这些块怎样落实为部署。基本分片与合并关系在正文说明，取整、候选枚举和装箱步骤由补充材料承接。

第一段交代模型算子与目标硬件。说明权重矩阵的形状、节点平面边界及存储深度如何进入空间编译，建立二维矩阵到三维权重块的转换场景。

第二段解释块怎样形成。介绍输入维分片结果相加、输出维分片结果拼接的基本关系，再说明编译器依据第三章的模型确定三维尺寸、累加深度与执行时间。Vertical 的深度选择接到模拟累加与数字合并的时间取舍。

第三段解释块怎样落到硬件。权重映射给出副本的驻留节点，空间编译结合这一安排确定节点内的块位置。以部署产物及其运行时用途收束，接到 4.2.2 的执行过程。

叙述草稿：

空间编译器根据算子的权重矩阵和目标硬件配置生成 Weight-Cube。矩阵形状决定需要存储和计算的权重规模，节点的平面尺寸与存储深度约束块的三维占用。编译器据此确定矩阵分片和深度放置，将模型中的算子组织为可在目标硬件上执行的权重块。

矩阵沿输入维分片时，各片计算结果相加；沿输出维分片时，结果按输出区间拼接。编译器依据硬件的计算方式确定块尺寸，并使用第三章的时间模型计算执行时间。在垂直累加配置下，编译器比较候选深度的模拟累加与数字合并时间，选择总耗时最小的累加深度。

权重映射算法确定专家副本的驻留节点后，空间编译器将副本的权重块放入对应节点，检查容量并确定块坐标。容量检查与最终放置采用相同的几何约束。生成的部署记录块尺寸、空间位置、累加深度和执行时间，供运行时根据路由使用相应副本。

### 4.2.2 Inference Execution

本节说明给定部署、路由、执行副本与规约根后，框架怎样得到推理时间，按“共同模型—Decode 时延计算—Prefill 模拟”组织。先建立连续的数据流与资源约束，再从单 Token 与多 Token 的任务形态解释两种评价方法。阶段介绍用中文段首引导语组织。

候选评分记为 L(a,u)，完整 Decode 时延记为 J_D。评分由分发、节点累计计算与返回三个部分的最大分支时间形成，用于搜索中的方案比较；完整时延由包含共享链路依赖的关键路径计算给出。正文简述两者的时间关系，4.3.2 使用评分作选择，4.2.3 使用完整结果形成分解与诊断。四方向展开、剪枝细则与输入优先关系的完整证明由补充材料承接。

叙述草稿：

**共同模型。** 部署与当前路由确定待执行的专家，硬件模型给出计算时间及输入输出字节数。输入沿分发树送达选定的执行节点，同节点专家串行计算，结果沿规约树汇聚形成层输出；输出所在位置成为后继层的输入源。通信采用最短路径树，重合的输入分发链路只传输一次，并在分支节点复制数据。有向 Mesh 链路独立占用，单跳时间由传输字节数与带宽确定，同一链路上的传输串行执行。

**Decode 时延计算。** 单个 Token 按层推进，同节点的专家计算时间可以累加。MoE 层的输入与输出为同维度向量，单跳传输时间相等。输入先送到执行节点，专家完成计算后才产生结果。到达同一链路起点时，结果已经经历输入传输、计算与结果传输，传输路程至少与输入到该起点的最短路径等长。计算时间为正，因此共享链路上的输入先开始传输。框架据此由传输跳数确定输入到达时间，并将共享链路上的输入完成时间加入结果传输的前驱关系。各节点收齐本地与子分支结果后向父节点传输，按依赖顺序递推得到完整时延。结果传输仍需等待已占用的链路，等待时间随递推保留。层完成时间与规约根位置共同传递到下一层。

**Prefill 模拟。** 多个 Token 并发使用计算节点与链路，任务的开始时间随其他任务的执行变化。离散事件模拟器接收所选副本与规约根，维护任务依赖、节点与链路可用时间，并推进计算和传输完成事件。就绪计算任务按 Token 编号、计算阶段与就绪时间仲裁；任务完成后释放后继任务，继续执行共同的分发与规约规则。模拟器输出窗口完成时间及节点、链路的资源使用记录，供性能分析器计算吞吐和瓶颈指标。

正文以数据依赖和时间关系说明评价方法，函数名、工作数组与 CPU 计时由实现和实验记录持有。共同硬件约束集中在本节，副本与规约根的选择依据集中在 4.3.2；资源可用时间日历与事件仲裁在 Prefill 段说明。

### 4.2.3 Performance Profiler

Profiler 接收 Decode 的完整时延与时间分量、Prefill 的窗口完成时间与资源记录，形成指标与瓶颈分析，并向离线候选选择提供评价结果。Decode 以候选评分中的最长分支为基础，分解专家计算、节点内串行与 Mesh 传输，集合通信等待取完整时延与这三项之和的差值，量化通信争用与规约依赖增加的时间。Prefill 从节点计算工作量、链路传输工作量与程序依赖构建执行下界，并结合实际完成时间解释改善余量。4.2.2 说明时间怎样得到，4.2.3 说明结果怎样用于评价和分析，积分与完整下界推导由补充材料承接。

章节顺序保持 Overview、框架、算法。4.2 解释部署怎样形成、选择怎样执行、结果怎样分析；4.3 解释部署与运行选择如何作出。共同计算与通信规则集中 4.2，映射搜索和两阶段调度集中 4.3。三级标题按阅读需要使用，短内容可通过中文段首引导语组织。

### 4.3 Algorithms

本节沿离线部署与在线数据流的关系展开：权重映射决定各专家有哪些可用执行位置，数据流调度依据当前路由使用这些位置，组织输入分发、计算与结果汇聚。先让读者理解每项算法要形成什么结果，再说明选择依据及求解过程。

#### 4.3.1 Weight Mapping

开篇说明输入是模型、专家访问与硬件配置，输出是各专家的副本配置和驻留节点。部署影响输入需要送到哪里、哪些任务共享计算资源，以及输出如何汇聚，由此引出副本预算下的选择。

随后介绍两种初始化及递增预算过程：根据访问需求分配副本，再调整位置，并用框架评价候选。超图目标、跨层位置评价和选择规则接到各自解决的部署问题。副本的空间编译在 4.2.1 说明，算法围绕副本数量与节点安排展开。

#### 4.3.2 Dataflow Scheduling

本节先建立部署后的数据流，再解释沿这条数据流需要作出的选择，随后展开两阶段策略。叙述以层输入、激活专家、执行节点和层输出为对象，公式在决策关系建立之后出现。

开头草稿：权重部署后，当前路由确定每个 Token 激活的专家。调度器从各专家的驻留副本中选择执行位置，将输入从当前源节点分发到这些位置。各节点完成专家计算后，将结果送至汇聚节点形成层输出；该位置随后成为跨层执行链中下一层的输入源。调度器逐层重复这一过程，将固定的权重部署组织成随路由变化的数据流。

接着解释选择为何需要共同考虑。执行副本确定输入的传输目的地和计算所在节点，汇聚位置确定结果送往哪里及后继输入从哪里发出。副本选择会改变节点间的计算分布，汇聚选择会改变结果传输距离，因此两者共同影响一次层执行的完成时间。先把这些关系说清楚，再引入副本与规约根的联合选择。

**Decode。** 单个 Token 按层推进，当前层的输出就绪后才能继续后继执行。调度器使用 4.2.2 的候选评分 L(a,u)，比较执行副本与汇聚位置并选择评分最小的组合。框架随后调用关键路径计算得到入选方案的完整时延，规约根成为下一层的输入源。决策式承接已经说明的数据流和时间模型，符号对应输入源、执行节点及汇聚节点；候选组合和搜索细则在机制明确后介绍。

**Prefill。** 多个 Token 并发经过上述数据流，高频专家会被反复调用。调度器在副本分派中累计各节点已分配的计算时间，选择加入当前任务后工作量较小的节点并更新累计量，使计算分散到可用副本。

副本确定后，调度器根据本层的执行节点选择规约根，优先减少规约树的链路数，并在并列候选中缩短最远结果的传输距离。输入从当前源节点沿分发树送达执行节点，计算结果沿规约树汇聚至所选根节点；层输出在该节点形成，并作为后继层的输入。Prefill 每次层调用根据执行节点集合确定规约根，选择准则保持一致。

正文先解释副本分流与结果汇聚，再给出累计工作量的选择式和规约根的主要选择依据。规约根的完整并列规则依次比较最大距离、总距离和节点编号，由补充材料交代。分发树与规约树按 4.2.2 的共同规则构造，执行中的资源仲裁由模拟器推进。

4.2.2 定义共同执行模型、候选评分与完整时延计算，并说明 Prefill 的资源日历和事件仲裁；4.3.2 从运行策略角度解释当前输入送到哪些副本、结果在哪里汇聚、输出怎样进入后继层。数据流叙述用这一连续过程引出决策，公式引用已建立的时间关系，结果分解与瓶颈解释由 4.2.3 持有。
